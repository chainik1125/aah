### Validation: clustering scheme vs exact at U=0

At U=0 (free fermions, V=0), the clustering scheme only truncates interactions — there are none, so it should be exact. Verified by comparing Nc=2,4,6,8 cluster energies against the exact finite periodic free fermion energy (analytically: E = -2t Σ cos(k) over occupied k = 2πn/L). Results at L=48:

- Nc=2 cluster: 0.0000% error (half-fill), 0.0000% error (quarter-fill)
- Nc=8 cluster: 0.0002% error (half-fill), 0.0001% error (quarter-fill)
- PBC DMRG chi=128: 0.44% error (half-fill), 0.20% error (quarter-fill)

**Conclusion:** The clustering scheme is exact at U=0 as expected. Any error shown in Fig 4 at U=0 when using PBC DMRG as the reference is from PBC DMRG chi-convergence (gapless system), not from the clustering. The finite periodic Bethe ansatz (`lieb_wu_energy_general_filling(..., bethe_mode='finite', finite_L=48)`) agrees with the exact free fermion energy to machine precision at U=0.

## RunPod execution notes

Running computations on the RunPod CPU instance (96-core Xeon 6342, 503GB RAM) requires the following environment setup to avoid pathological performance:

1. **Disable GPU eigensolver fallback**: `CUDA_VISIBLE_DEVICES=-1` must be set **before Python starts** (as a shell env var, not `os.environ` inside Python). The RunPod container has an A40 GPU; CuPy detects it at import time in `hamiltonian.py` and attempts GPU eigensolves that fail with "Eigenvalues did not converge", adding minutes of overhead per eigensolve before falling back to CPU.

2. **Pin BLAS threads**: `OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1` to prevent thread oversubscription on 96 cores. Without this, each eigensolve spawns 96 BLAS threads and the contention makes everything slower.

3. **Use v_sep_ratio=(1,1) when V=0**: The function `compare_filling_with_int_cluster_sizes` handles this automatically, but manual scripts must pass it explicitly. Using v_sep_ratio=(1,2) at V=0 causes unnecessary cluster fusion, inflating Hilbert space dimensions and turning 2s tasks into 30+ minute hangs.

4. **Nc=8 may hang in compressibility**: `compare_compressibility_with_int_cluster_sizes` hangs on Nc=8 (no output, full CPU). Run with Nc up to 6 only until this is investigated.

**Recommended RunPod invocation:**
```bash
CUDA_VISIBLE_DEVICES=-1 OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 python -m aah_code.cluster_model.cluster_runner ...
```

**Benchmark (2026-04-04):** Full Fig 2 ED (144 tasks, Nc=2,3,4, L=48): 139s serial, 21s with n_jobs=16 on RunPod.

## Filling staircase at U=0

The cluster ED filling curve ν(μ₀) shows a staircase structure at U=0 (non-interacting limit) with L/Nc plateaux. For Nc=2, L=48 this gives 24 steps at multiples of ν = 2/24 ≈ 0.083 per site. Verified with 200 μ₀ points — the staircase persists and is not a sampling artifact.

This is intrinsic to the method: at U=0, all L/Nc K-points have the same cluster spectrum (shifted by the twist phase), so they fill simultaneously as μ₀ sweeps. In contrast, OBC DMRG on a 48-site chain has 48 distinct single-particle levels spread across the band, giving a smoother curve. The discrepancy is a methodological difference (discrete cluster spectrum vs quasi-continuous chain spectrum), not an approximation error. At finite U, the interaction lifts this degeneracy and the meaningful physics is correctly captured.

Fine-grid data (200 μ points, cluster ED only, no DMRG): `compressibility_comparison_L48_chi32_20260404_223720.pkl`
